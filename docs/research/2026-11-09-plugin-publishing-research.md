# Polyglot is valid; rework it to stand out

The polyglot plugin is already **schema-valid and can be self-hosted today**. Its plugin.json, marketplace.json, root `.lsp.json`, hooks.json wrapper and skill frontmatter all use documented fields. Neither `polyglot` nor `polyglot-marketplace` breaks a reserved-name rule ([Manifest ref](https://code.claude.com/docs/en/plugins-reference); [Marketplace ref](https://code.claude.com/docs/en/plugins/marketplace-reference)). What stands between it and a credible, directory-ready release is less a schema problem than three others. The first is **policy exposure**. A Buy Me a Coffee link is printed by a script whose output reaches Claude, which falls under the Directory Policy's ban on "sponsored content". "Andrej Karpathy" also appears in the plugin's description, keywords and a skill name, and the directory holds any name that matches "a well-known brand that isn't yours" ([Software Directory Policy](https://support.claude.com/en/articles/13145358-anthropic-software-directory-policy); [Pre-submission checklist](https://claude.com/docs/plugins/pre-submission-checklist)). The second is **hook engineering**. `MultiEdit` is no longer a Claude Code tool. A 30 s timeout around whole-project `tsc`/`cargo check` cuts short the very checks that make the hook valuable. A PostToolUse hook also cannot prevent an edit; it can only report one after the fact ([Hooks reference](https://code.claude.com/docs/en/hooks)). The third is **differentiation**. All 12 of Anthropic's official LSP plugins cover languages polyglot re-declares ([official marketplace.json](https://raw.githubusercontent.com/anthropics/claude-plugins-official/main/.claude-plugin/marketplace.json)). The four "Karpathy principles" already ship as a ~231k-star plugin ([multica-ai/andrej-karpathy-skills](https://github.com/multica-ai/andrej-karpathy-skills)). The open niche is **deterministic, multi-language enforcement**: blocking type-escape hatches before the write, and gating on compilers. Nobody else ships that, so the plan below rebuilds the plugin around it.

## Every manifest passes; two hook details need fixing

The manifest needs only `name`. `repository` is a plain string, and `author` is an object whose `name` is required, so polyglot's plugin.json is correct as written, including the SPDX `license: "MIT"` ([Manifest ref](https://code.claude.com/docs/en/plugins-reference)). The release checklist recommends two optional fields it lacks: `displayName`, which is the label users see, and `homepage`, which "must parse as a URL" ([Publish](https://code.claude.com/docs/en/plugins/publish.md)). The marketplace file is also valid. **Top-level `description` and `version` are documented fields**, and `"source": "./"` for a plugin at the repository root is explicitly supported. Setting `version` in both the marketplace entry and plugin.json is legal, but it creates a drift hazard. If the two values differ, validate warns `At install time, plugin.json wins` ([Marketplace ref](https://code.claude.com/docs/en/plugins/marketplace-reference)).

The root `.lsp.json` is in the default location. Each of its 18 entries uses only the keys `command`, `args`, `extensionToLanguage` and `initializationOptions`, all of which are allowed. The file has two traps, though. **LSP configs are strict, so a single unknown key in any one entry silently skips the whole file**. **`claude plugin validate` doesn't read `.lsp.json` at all**, so a typo surfaces only in the `/plugin` Errors tab ([Components](https://code.claude.com/docs/en/plugins/components)). Substitution of `${CLAUDE_PLUGIN_ROOT}` inside `initializationOptions` works only from v2.1.288 ([CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)). Two runtime caveats change what users can expect. Servers are launched by name from `PATH` and are never bundled. And **"In cloud sessions, Claude Code doesn't start plugin language servers"** ([Code intelligence](https://code.claude.com/docs/en/plugins/code-intelligence)).

The hooks file correctly wraps its event map in a top-level `"hooks"` key. A file without that wrapper fails to load ([Manifest ref](https://code.claude.com/docs/en/plugins-reference)). One research note claimed the command is unquoted. It is not. The actual value is `"\"${CLAUDE_PLUGIN_ROOT}/scripts/verify-edit.sh\""`, which wraps the variable and the path in one quoted string. The validator warns only when the variable sits "outside quotes", so this form is very likely fine. The documented spelling is `"\"${CLAUDE_PLUGIN_ROOT}\"/scripts/format.sh"`, and running `claude plugin validate . --strict` will confirm whether either form passes ([Manifest ref](https://code.claude.com/docs/en/plugins-reference)). The matcher is a different story. **`MultiEdit` appears nowhere in the current tools reference.** The built-in edit tools are `Edit`, `Write` and `NotebookEdit`, and the official example matcher is `Write|Edit` ([Tools reference](https://code.claude.com/docs/en/tools-reference)). The dead entry is harmless, but it signals stale configuration to reviewers.

All five frontmatter fields the skills use (`name`, `description`, `when_to_use`, `argument-hint`, `effort`) are supported in Claude Code. The cap is **1,536 characters for `description` plus `when_to_use` combined**. Outside Claude Code, in claude.ai uploads and the Skills API, `when_to_use`, `argument-hint` and `effort` cause a hard error ([Skills](https://code.claude.com/docs/en/skills)). That matters only if the skills are ever uploaded on their own.

## The hook reports after the fact and times out on real projects

PostToolUse cannot block. The docs' exit-code table says exit 2 "Shows stderr to Claude; the tool already ran". Plain stderr on exit 0 never reaches Claude. Feedback is capped at **10,000 characters** before it spills to a file and is replaced by a 2,000-character preview ([Hooks reference](https://code.claude.com/docs/en/hooks)). verify-edit.sh therefore uses the correct feedback channel, but its grep for `@ts-ignore`, `as any` and `# type: ignore` runs after the escape hatch is already on disk. Stopping the edit itself requires a **PreToolUse** hook that inspects `tool_input` and denies with exit 2 or `permissionDecision: "deny"`. No published plugin does this for multiple languages ([Hooks reference](https://code.claude.com/docs/en/hooks); [competitive survey, systemprompt.io](https://systemprompt.io/guides/claude-code-hooks-workflows)).

The 30 s timeout is self-imposed, because the default for command hooks is **600 s** ([Hooks reference](https://code.claude.com/docs/en/hooks)). A whole-project `npx tsc --noEmit` or a cold `cargo check` can exceed 30 s. A hook that fails "in some other way" becomes a non-blocking error, so a timeout most likely gives Claude no feedback at all. That is an inference, because the docs don't quote the timeout notice. Matching hooks also run in parallel, so rapid edits each start a full compile. Latency is the community's top complaint about this hook pattern. The usual fixes are incremental or per-file checks on edit with the full check moved to Stop or commit ([understandingdata](https://understandingdata.com/posts/claude-code-hooks-quality-gates/); [DEV](https://dev.to/ohugonnot/claude-code-hooks-real-examples-posttooluse-stop-pretooluse-620)). The platform now provides the right tool for slow checks: **`asyncRewake: true` runs a hook in the background and wakes Claude only on exit 2** ([Hooks reference](https://code.claude.com/docs/en/hooks)). The script also tests `[[ -f tsconfig.json ]]` relative to the process working directory. Hooks run in Claude's current directory, so the project root should come from `$CLAUDE_PROJECT_DIR` or from walking up from the edited file. The hooks guide also asks scripts to reject `..` paths and skip `.env` and `.git/` ([Hooks reference](https://code.claude.com/docs/en/hooks)). The best available benchmark is bartolli's TS-only hook. It checks only the edited file against its nearest tsconfig, caches the result, and reaches checks under 5 ms, at the cost of missing cross-file errors ([bartolli/claude-code-typescript-hooks](https://github.com/bartolli/claude-code-typescript-hooks)).

## Directory rules turn branding and sponsorship into review risks

Self-hosting has no gate. "Once the file is in the repository, the plugin is published, with no submission form." Users then run `claude plugin marketplace add tahmidbintaslim/claude-code-polyglot` followed by `claude plugin install polyglot@polyglot-marketplace` ([Publish](https://code.claude.com/docs/en/plugins/publish.md)). Auto-update is **off by default** for third-party marketplaces, so the README should tell users to run `claude plugin update` ([Install plugins](https://code.claude.com/docs/en/discover-plugins)). The Anthropic directory is a different path. Submissions go through the portal at claude.ai/directory/manage as a "Plugin bundle", and **a paid plan is required**. `claude-plugins-official` does not accept portal submissions. Every version gets automated validation and a security scan, and a person reviews each new listing on no fixed timeline ([Publish to the directory](https://claude.com/docs/directory/publish); [Submit your plugin](https://claude.com/docs/plugins/submit)). Approved plugins are mirrored to `claude-plugins-community`, where pull requests are closed automatically ([anthropics/claude-plugins-community](https://github.com/anthropics/claude-plugins-community)).

The pre-submission checklist maps directly onto polyglot's files ([Pre-submission checklist](https://claude.com/docs/plugins/pre-submission-checklist)):

| Checklist rule | Outcome | polyglot exposure |
|---|---|---|
| Scripts with launchers (`npx`, `uvx`), installs, or other shell variables are held | Held | `verify-edit.sh` runs `npx --no-install tsc` |
| `name`/`displayName`/`author.name` resembling a well-known brand that isn't yours | Held | Karpathy in description, keywords, `karpathy-core`, `.cursor/rules/polyglot-karpathy.mdc` |
| Names made only of generic words | Held | `polyglot` is one generic word; another org may also own it ("Name is taken" Blocks) |
| README ≥40 words; LICENSE or `license` field | Blocks if absent | Already satisfied |
| README must "Describe … everything the plugin runs, sends, or fetches" | Scan finding | Must list every compiler/linter the hook invokes |
| Hook/MCP commands use full `${CLAUDE_PLUGIN_ROOT}` paths | Blocks | Already satisfied |

Directory Policy **4C** excludes software that "serves advertisements, sponsored content, or paid product placements" without written permission ([Software Directory Policy](https://support.claude.com/en/articles/13145358-anthropic-software-directory-policy)). `lsp-doctor.sh` echoes a Buy Me a Coffee URL, and the `doctor` skill runs that script, so the link lands in Claude's context. That is the clearest 4C exposure. README badges and `.github/FUNDING.yml` are not addressed by the policy and are customary. Nothing found states an Anthropic rule specifically on real people's names. However, the Trademark Guidelines forbid implying endorsement ([Trademark Guidelines](https://www.anthropic.com/legal/trademark-guidelines)). The Directory Terms forbid implying partnership ([Software Directory Terms](https://support.claude.com/en/articles/13145338-anthropic-software-directory-terms)). The checklist's brand hold also applies. Karpathy did not write or endorse the principles repo these skills echo ([AlphaSignal](https://alphasignalai.substack.com/p/karpathy-inspired-claudemd-how-to)). Descriptive skill names, plus a README line crediting his January 2026 post with an explicit no-affiliation note, remove the risk at little cost. The repo name `claude-code-polyglot` is not checked by Claude Code. Calling the product "Polyglot, a plugin for Claude Code" with a non-affiliation disclaimer follows common practice. Community lists are looser. awesome-claude-code accepts only web-form issues, for resources at least **14 days old or with 100+ stars**, and wants "a description, not a sales pitch" ([CONTRIBUTING](https://github.com/hesreallyhim/awesome-claude-code/blob/main/CONTRIBUTING.md)). claudemarketplaces.com crawls GitHub automatically ([claudemarketplaces.com](https://claudemarketplaces.com/)).

## Re-declaring official LSPs adds conflicts, not value

Anthropic ships 12 single-language LSP plugins: clangd, csharp, gopls, jdtls, kotlin, lua, php, pyright, ruby, rust-analyzer, swift and typescript. typescript-lsp alone has **212,522 installs** ([marketplace.json](https://raw.githubusercontent.com/anthropics/claude-plugins-official/main/.claude-plugin/marketplace.json); [claude.com/plugins/typescript-lsp](https://claude.com/plugins/typescript-lsp)). polyglot re-declares all 12 languages. Only Zig, Elixir, Dart, Bash, Terraform and R are unique to it, and Piebald-AI/claude-code-lsps already covers most of those ([Piebald](https://github.com/Piebald-AI/claude-code-lsps)). Duplication carries a real cost. Each extension gets exactly one server: the first one registered wins, and the others log `is not used for <ext> files` ([Components](https://code.claude.com/docs/en/plugins/components)). A user who already has typescript-lsp gets warnings and unpredictable ownership of the extension. Claude Code will also recommend the official plugin when it detects a matching binary ([Code intelligence](https://code.claude.com/docs/en/plugins/code-intelligence)). The guidance skills face the same saturation. The four principles (Think Before Coding, Simplicity First, Surgical Changes, Goal-Driven Execution) already exist as an installable plugin with about 231k stars, plus many clones ([multica-ai](https://github.com/multica-ai/andrej-karpathy-skills); [skills.sh](https://skills.sh/ninehills/skills/karpathy-guidelines)). superpowers already owns verification and TDD workflows ([obra/superpowers](https://github.com/obra/superpowers)).

The unoccupied position is enforcement. That repo is advisory text, and the docs themselves advise: "Claude skipped a rule that must hold every time: move the rule into a hook" ([Skills](https://code.claude.com/docs/en/skills)). bartolli's hook covers only TypeScript and merely warns on `as any` ([bartolli](https://github.com/bartolli/claude-code-typescript-hooks)). tdd-guard gates on TDD, not types ([tdd-guard](https://github.com/nizos/tdd-guard)). Anthropic's hookify is generic ([marketplace.json](https://raw.githubusercontent.com/anthropics/claude-plugins-official/main/.claude-plugin/marketplace.json)). cclsp's setup wizard, which detects languages and installs servers, is the closest model for a "doctor" experience ([cclsp](https://github.com/ktnyt/cclsp)). polyglot's pitch should therefore be: **"one install that blocks type-escape hatches before they land and gates edits on the real compiler, in 18 languages, and works with the official LSP plugins rather than replacing them."** The hook also earns its keep where LSP is absent, because cloud sessions start no language servers.

## Conclusion

Correctness is the cheap part: about an hour of edits plus `claude plugin validate . --strict`. The decisions that matter are positioning and policy. Promotional output and a borrowed name are what would stall a directory review, not the JSON. LSP duplication creates conflicts with the most-installed plugins in the ecosystem instead of adding value. The real asset, a cross-language PreToolUse plus PostToolUse gate, currently runs too late and too slowly to deliver its promise. Some things stay unknown until the portal's Validate step runs: whether `polyglot` is already taken by another org, whether a single generic word triggers a hold, and how strictly connector-oriented items such as "3 example prompts" apply to plugin bundles. Plan for one rename and one resubmission.

# HatchLock as an MCP server: spec, SDK, registries, Context7 (researched 2026-11-17)

## 1. Spec + implementation
- Current MCP spec: **2026-07-28** (https://modelcontextprotocol.io/specification/versioning). It is per-request versioning: `_meta["io.modelcontextprotocol/protocolVersion"]` plus a mandatory `server/discover` RPC. Handshake-based revisions (`2025-11-25` and earlier) are handled through a backward-compat section, so clients that still send `initialize` have to work.
- SDKs (https://modelcontextprotocol.io/docs/sdk): TS, Python, Go, Rust, C#, and Ruby are Tier 1.
- TS SDK v2 (https://github.com/modelcontextprotocol/typescript-sdk): packages `@modelcontextprotocol/server` and `/client`. It was released 2026-07-27 and implements 2026-07-28. Schemas use Standard Schema (zod v4 optional). v1 (`@modelcontextprotocol/sdk`) gets fixes for at least 6 months.
- Python SDK: the README links "What's new in v2" and uses an `MCPServer` class. Its spec support and dependency list were NOT verified (https://py.sdk.modelcontextprotocol.io/).
- Recommendation: a single-file Node server on TS SDK v2 that shells out to the existing bash scripts. Publish to npm and run with `npx -y hatchlock-mcp@X.Y.Z`. Node is already present wherever Claude Code, Cursor, or VS Code run, while Python and uv are less universal.
  - Zero-dependency hand-rolled JSON-RPC is possible (stdio is newline-delimited JSON). It is risky because of dual handshake and per-request versioning; that dual-version support is the reason to use the SDK.
  - All bash, using jq, would be the most transparent option for Anthropic's validator, which "follows only plain shell scripts". It is fragile, so we skip it.

## 2. Official MCP Registry
https://raw.githubusercontent.com/modelcontextprotocol/registry/main/docs/modelcontextprotocol-io/quickstart.mdx
- Status: **preview**. Breaking changes or data resets are possible. It hosts metadata only.
- Namespace with GitHub auth: `io.github.<user>/<name>`.
- npm ownership: `package.json` needs `"mcpName": "io.github.tahmidbintaslim/hatchlock"`, and it must equal `server.json` `name`.
- `server.json` `description` must be ≤100 chars. Schema: https://static.modelcontextprotocol.io/schemas/2025-12-11/server.schema.json
- Steps: `brew install mcp-publisher` (or the release binary), `npm publish --access public`, `mcp-publisher init`, `mcp-publisher login github` (device flow), `mcp-publisher publish`. Verify with `curl "https://registry.modelcontextprotocol.io/v0.1/servers?search=io.github.<user>/hatchlock"`.
- Fields (https://github.com/modelcontextprotocol/registry/blob/main/docs/reference/server-json/generic-server-json.md): `packages[].registryType` (npm/pypi/nuget/oci/cargo/mcpb), `identifier`, `version`, `runtimeHint` (npx/uvx), `transport.type` (stdio), `packageArguments`, `environmentVariables`.

```json
{
  "$schema": "https://static.modelcontextprotocol.io/schemas/2025-12-11/server.schema.json",
  "name": "io.github.tahmidbintaslim/hatchlock",
  "description": "Blocks new type-check escape hatches and runs per-file/project compiler checks locally.",
  "repository": { "url": "https://github.com/tahmidbintaslim/HatchLock", "source": "github" },
  "version": "0.1.0",
  "packages": [{
    "registryType": "npm",
    "identifier": "hatchlock-mcp",
    "version": "0.1.0",
    "runtimeHint": "npx",
    "transport": { "type": "stdio" }
  }]
}
```

## 3. Directories / clients
- **Anthropic directory** (https://claude.com/docs/directory/publish.md): MCPB/desktop-extension listings are **deprecated and no longer accepted**. A local server must ship inside a **plugin bundle**, submitted at claude.ai/directory/manage (paid plan).
- **Plugin checklist** (https://claude.com/docs/plugins/pre-submission-checklist.md):
  - Launchers must be pinned (`npx pkg@1.2.3`, `uvx pkg==1.2.3`); unpinned blocks.
  - Even a pinned launcher is **always held for review** ("Runs a pinned npx or uvx package").
  - A lockfile install is held, and a non-shell server file (e.g. `node ${CLAUDE_PLUGIN_ROOT}/server.js`) is held ("Scripts the validator couldn't follow").
  - `.mcpb` in a plugin is held, and blocks if fetched from a URL.
  - README of 40 words or more and a LICENSE are required. No `.npmrc`.
- **Where local servers run** (https://claude.com/docs/plugins/platform-support.md): a local MCP server is **ignored in claude.ai Chat**, loads in Cowork when it runs locally, and loads in Claude Code. claude.ai web can't use a stdio server.
- **ChatGPT dev mode / apps** (https://developers.openai.com/api/docs/guides/developer-mode.md): it supports only **SSE and streaming HTTP**, so no stdio. The only option for a local server is a "Secure MCP Tunnel" (plan gating unclear). Codex CLI supports stdio (not re-verified here).
- **Cursor** (https://cursor.com/docs/context/mcp): stdio is supported, configured in `.cursor/mcp.json` or `~/.cursor/mcp.json`. Listing goes through the Cursor Marketplace (official plugins) or cursor.directory (community). The submission process is not documented on that page.
- **GitHub/VS Code MCP registry**: entries self-published to the official registry are said to flow into GitHub's registry (https://github.blog/ai-and-ml/github-copilot/meet-the-github-mcp-registry-the-fastest-way-to-discover-mcp-servers/, Sep 2025). The 2026 state was NOT verified.
- **PulseMCP** (https://www.pulsemcp.com/submit): submissions are paused. It says to publish to the official registry, which it will ingest.
- **Glama**: auto-indexes GitHub. Claim the listing by adding `glama.json` `{"$schema":"https://glama.ai/mcp/schemas/server.json","maintainers":["<gh-user>"]}` (https://glama.ai/blog/2025-07-08-what-is-glamajson).
- **Smithery**: the docs say local servers are distributed as `.mcpb` (`smithery mcp publish ./server.mcpb -n org/name`). The doc URLs 404ed for us, so this is UNVERIFIED.
- **Docker MCP Catalog** (https://github.com/docker/mcp-registry): you submit a PR with an image, which then runs containerized. It is a poor fit, because HatchLock needs host files and the host compilers.
- **mcp.so**: has a submit form. NOT verified.

## 4. Context7
- Sources: https://github.com/upstash/context7 (MIT for the MCP server; the backend is private) and https://context7.com/docs/resources/all-clients.
- Remote: `https://mcp.context7.com/mcp` with an `Authorization: Bearer KEY` header, or OAuth at `/mcp/oauth`.
- Local: `npx -y @upstash/context7-mcp --api-key KEY` (local stdio requires a key).
- The key is free at context7.com/dashboard and gives higher rate limits. Setup helper: `npx ctx7 setup --claude|--cursor`.
- Plugin bundling: a plugin `.mcp.json` may reference it as http `https://mcp.context7.com/mcp`. The key must come via `userConfig` (sensitive) as `${user_config.KEY}`; hard-coded secrets block. MCP servers using `${user_config}` in a header load in Claude Code but are ignored in Chat and may be ignored in Cowork.
- Simplest: OAuth, with no header and no key; Anthropic's guidance favors a remote URL.
- Verdict: point to Context7 and don't build our own docs server. HatchLock checks are local-only, and docs lookup is a separate, networked concern.
